# 写作档案：自动学习与积累

通用规范只能写到"大多数好论文怎么写"。具体到一个作者、一本期刊、一个导师，答案各不相同，
也没法预先写全。所以本技能给每位作者维护一份档案，起草前读取，改完后从作者的修改和反馈里学习。

档案默认在 `~/.claude/prose-profile/`，可用环境变量 `PROSE_PROFILE_DIR` 改位置。它不在技能目录里，
技能公开分享时不会带出个人内容。第一次用时运行 `python ~/.claude/skills/prose/scripts/profile.py init`。

借鉴说明：从用户修改里推断可读的偏好描述、按场景存取，借自 CIPHER（Gao 等，NeurIPS 2024，arXiv 2404.15269），
这里把向量检索改成按"文体 / 期刊 / 章节"匹配，档案存成作者能直接编辑的 Markdown；"单次观察不直接成规则"的晋升门槛借自
self-learning-skills（MIT）；按信号强弱分级、改动可追溯的做法参考了 claude-reflect-system 的思路。

## 1. 起草前：读档案

```bash
python ~/.claude/skills/prose/scripts/profile.py context --genre academic-en --venue TIFS --section intro --lang en
```

输出里有四样东西，按这个顺序用：
1. 适用规则：照做。越具体的越优先，同等具体时新的优先。和期刊硬性要求冲突时，按期刊。
2. 期刊卡片：投稿要求和从范文里学到的结构规律，用来定骨架和篇幅。
3. 范文结构卡片：照着它的结构清单写，逐条核对（AGENTS.md 的参考样例规则）。
4. 作者样稿：取 2–3 段同文体的，按 [prevention.md](prevention.md) 的 T1 模板作风格样本，学习惯，不抄词句。
另外，`--genre` 下的术语表要全文遵守。

档案为空时照常按通用规范写，不要因为没有档案而停下来。

## 2. 交付后：从修改里学

学习的信号，按可靠程度排：
- explicit：作者明确说"以后都这样""记住""不要再写成 X"。最可靠，可以直接升为规则。
- user-edit：作者改了我交付的稿子。拿到定稿后运行 `profile.py diff 我的稿 定稿`，逐处看改了什么。
- advisor / reviewer：导师批注、审稿意见里关于写法的部分。
- exemplar：作者指定的范文（见第 4 节）。

从每处修改里归纳"为什么这样改"，写成一条在别的段落也成立的偏好。不是每处修改都值得记：
- 记：反复会遇到的选择。例如"贡献句用 We 主动句""结果先给差值再给绝对值""不用 respectively""'图像篡改'不写成'图像伪造'"。
- 不记：只针对这一段内容的修改（改了一个事实、补了一个引用）、改正我的事实错误（那是错误，不是偏好）、一次性的语气调整。
- 不记：作者把文字改得更像 AI 腔的修改，除非作者明确坚持。

记录前先查 `observations.md` 里同一范围有没有意思相同的条目：有就 `observe --same O编号`，没有才新建。

```bash
python ~/.claude/skills/prose/scripts/profile.py observe --scope academic-en/TIFS/intro --lang en --src user-edit \
  --pref "贡献句用 We 主动句陈述，不用被动" --example "A novel framework is proposed → We propose a framework"
```

范围取得越窄越安全：只在 TIFS 引言里观察到的，就记成 `academic-en/TIFS/intro`，不要记成 `*/*/*`。
同一条在两个以上期刊或章节里都出现了，再在升级时放宽范围。

## 3. 升级成规则

- 同一观察在不同文稿里出现两次（n≥2），或者来源是 explicit：在交付说明里用一句话问作者"要不要把这条记为规则"。
  作者同意才运行 `profile.py promote O编号`；作者改了措辞，用 `--pref` 写入改后的。
- 不同意就不升级；作者说这条不对，就把观察删掉。
- 规则过时或者作者改了主意：`profile.py retire R编号 --reason "…"`。停用的规则留在文件末尾作历史，不再生效。
- 升级和停用都在交付说明里告诉作者一句，不悄悄改。

## 4. 学一本期刊或一类范文

作者说"学一下这几篇的写法""我要投 X，看看他们怎么写"时：
1. 范文优先用作者给的；作者没给时，先问能否检索，同意后用 `lit-scout` 或 `agent-reach` 找该刊近两年录用的 3–5 篇同方向论文，
   附链接让作者确认。
2. 每篇按 `exemplars/_card-template.md` 做一张结构卡片，存到 `exemplars/<文体>/`。只记结构和写法要点，用自己的话概括，
   原文引用每处不超过一句，不存全文。
3. 读该刊的作者指南，把硬性要求写进 `venues/<期刊>.md`，附链接和查阅日期。
4. 三篇以上卡片里共同出现的结构规律，写进期刊卡片的"结构规律"一节，并注明基于几篇；只在一篇里出现的不写成规律。
5. 期刊卡片一年左右或作者指南改版时更新。

## 5. 样稿与写作习惯统计

作者自己满意的文字（导师认可的段落、已录用论文的正文）放进 `samples/`，文件名以文体开头。可以用
`profile.py stats samples/academic-en_*.md` 统计作者本人的习惯，包括句长分布、段长、we 和被动的密度、限定语和强调语的密度、破折号。
这些数字用来校准改写，避免把作者的文字改成另一个人的口吻，不是好坏标准。

## 6. 维护

- 规则超过 40 条，或者每次读档案时规则明显互相重复：合并意思相同的条目，停用过时的，保留最具体、最新的写法。
- 发现两条规则冲突：按"具体优先、新的优先"执行，并在交付说明里请作者裁定，裁定后停用输掉的那条。
- 每次写入前，脚本会把原文件备份成 `.md.bak`。

## 7. 边界

- 档案里的规则不能覆盖硬边界（信息守恒、不编造、不改数字和限定）和期刊的硬性要求。
- 只学作者本人的偏好。别人的稿件（帮同学或审稿时看到的）不写进档案，不进样稿库。
- 不存密码、未公开数据、审稿保密内容；审稿意见只记录关于写法的结论，不记原文。
- 范文和作者指南只存结构卡片和短摘，不存受版权保护的全文。
- 不确定一条修改是不是偏好时，宁可不记。档案的价值在于每条都可信，不在于条数多。
