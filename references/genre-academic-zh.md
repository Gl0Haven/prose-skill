# 文体：中文学术（期刊论文、学位论文、综述、开题、绪论、调研笔记）

人设：同领域资深同门。读者是内行，不解释常识；作者读过这个方向绝大多数关键工作，
手里有一张"谁做了什么、谁接着谁"的地图。"我"只用于表态，不编经历。

整体写法（一个核心贡献、引言弧线、写作顺序、各部分职能）见 [academic-method.md](academic-method.md)，中英文论文通用；
本文件补中文期刊和国标的要求。起草前先 `profile.py context`（[learning.md](learning.md)），用目标期刊的卡片和作者的规则。
证据标记：[规范] 国标或期刊明文；[实测] 读论文统计到的；[观察] 经验归纳。

## 两种语域
- 笔记体（自己或同门看的调研笔记、读书笔记）：直给结论；允许"我的判断是""这条线基本停了""其余几篇大同小异，不展开"；句子可以短到一个分句。
- 投稿体（期刊论文、综述、开题、学位论文）：正式，但仍守同一套逻辑；口语判断换成学术表述
  （"这条线基本停了"→"该方向近年鲜有后续，已逐渐被 X 取代"）。成段叙述，不用列表。

## 国标的硬要求
现行标准：学术论文 GB/T 7713.2—2022；学位论文 GB/T 7713.1—2006；摘要 GB/T 6447—2025（2026-02-01 起实施，代替 1986 版）；
关键词 CY/T 173—2019；参考文献 GB/T 7714—2015；标点 GB/T 15834—2011。条款号据原文核对，7714、15834 原文未取得 [规范]。

| 项目 | 要求 |
|---|---|
| 题名 | 简明、恰当，用标准术语，不用广义术语和夸张词语，一般不超过 25 字，宜有英文题名（7713.2 4.2.1）；学位论文题名通常是名词性短语，避免不常用缩略语和公式（7713.1） |
| 摘要 | 不加注释和评论，独立、自明；含目的、方法、结果、结论；宜用报道性摘要；首次出现的缩略语给全称；不含图表和公式的编号（7713.2 4.2.3）。报道性约 400 字、报道-指示性约 300 字、指示性约 150 字（6447 4.2）。方法、结果、结论写详细，目的写简略；不写本领域常识，不重复题名（6447 第 5 章、7.2–7.3）。作者自己写的摘要可以用"本文""我们""笔者"（6447 6.1.3）。学位论文中文摘要一般 300~600 字（7713.1） |
| 关键词 | 3~8 个，有检索意义，不用"方法""理论""分析"这类太泛的词，宜标英文（7713.2 4.2.4）；研究对象、方法、限定因素作为必要因素标引（CY/T 173 6.1） |
| 引言 | 背景、目的、理由、预期结果及意义；切合主题、言简意赅、突出重点和创新点；客观评介前人，如实介绍自己的成果（7713.2 4.3.2）。学位论文的文献回溯和理论分析要独立成章（7713.1 5.3.1） |
| 主体 | 完整描述理论、方法、假设、程序和参数选择，让同行能重复（7713.2 4.3.3） |
| 结论 | 对结果和论点的提炼，不是摘要或各章小结的重复；推不出结论时写"结束语"（7713.2 4.3.4）。学位论文的结论还要交代局限、提出未来工作（7713.1 5.3.7） |
| 层次 | 章节一般不超过 4 级，章节标题一般不超过 15 字，引言编号可为"0"（7713.2 5.2.2） |
| 图表 | 图有自明性，图题在图下，表题在表上，先见文字后见图表；表头不用斜线，不用"同上""同左"（7713.2 5.4–5.5）；学位论文建议三线表 |
| 量和单位 | 量符号斜体、单位符号正体；数值与单位符号之间留空隙；不用 rpm、ppm 这类缩写当单位；相乘量重复写单位（40 m × 60 m）（7713.2 5.3） |
| 数字 | 计量计数用阿拉伯数字；有效数字写全（1.50 不写成 1.5）；大于 999 的整数三位分节（7713.2 5.6） |
| 公式 | 式后用"式中"逐一解释符号；不用量的名称或多字母缩略语（如 MSE）代替量符号（7713.2 5.7） |

## 期刊差异：以目标刊物当前的须知为准

| 项目 | 《计算机学报》 | 《软件学报》 | 《自动化学报》 | 《电子与信息学报》 |
|---|---|---|---|---|
| 摘要 | 必须含问题与目的、方法（重点）、结果与结论、创新之处；"用具体数据说明成果优势"，不写"大大提高""显著改善" | 未见字数明文 | 规定一般不超过 200 字，不放图表、文献序号和公式 | — |
| 英文摘要 | 约 500 字，与中文对应；另附约 400 词英文研究背景 | — | 与中文内容一致 | 含英文长摘要 |
| 结构 | 相关工作必须与引言分开、单独成节；研究论文须有对比实验 | 必须与国内外同类工作详细比较；只引英文文献不引中文会被退稿 | — | — |
| 参考文献 | 只列最主要的、按引用顺序 | 须补国内同类工作并比较 | 顺序编码制 | 不少于 15 条，近两年的占 30% 以上 |
| 篇幅 | 研究论文双栏 13 页或以上（"不是越长越好"） | 投稿时不限 | — | 研究型 18 页以内，综述 25 页以内 |

以上读自各刊官网，2026 年 11 月 [规范]；《通信学报》《信息安全学报》《中国科学：信息科学》的须知未取得。
规定和实际有差距：《自动化学报》规定摘要不超过 200 字，但读到的三篇有 387~1010 字；2025–2026 年《计算机学报》《软件学报》的摘要实测 390~649 字 [实测]。
中文摘要的常态是 400~600 字的一段，别机械套 200 字或 400 字；动笔前看目标刊最近几期，做成期刊卡片。

## 各部分的写法
- **题名**：常见形式是"基于 X 的 Y 方法 / 模型"、"面向 X 的 Y"、"X 研究综述"，方法有名字时可用"方法名：中文副题" [实测]。
  这些形式本身没问题，要避免的是"的"字层层堆叠（题名里"的"不超过两个）、"研究""探讨""浅析"凑数，以及"新颖的""高效鲁棒的"这类没有度量的修饰。
  题名要同时含问题对象和方法的关键特征，不读摘要也知道"解决什么、靠什么"。
- **摘要**：常见顺序是背景一两句 → 现有方法的具体缺陷（"然而""但"引出）→"为此，本文提出……，其核心思想是……" → 机制 → 实验规模和带数字的结果 → 一句意义 [实测]。
  背景尽量少（《计算机学报》转述 EI 的要求）；提升要说清是绝对百分点还是相对比例。人称选"本文"或省略主语都行（《软件学报》常省略，《计算机学报》常写"本文"），全文统一。
- **引言**：研究背景与应用价值 → 现有方法的分类与缺陷 → 收束成一个具体问题 → 本文的总体做法 → 新意 → 贡献三条左右 → 结构安排 [实测]。
  贡献每条写成审稿人能核查的陈述，例如"（1）针对……问题，提出……；（2）设计……；（3）在……上的实验表明，……提高 a 个百分点"，不写"具有重要意义"。
- **相关工作**：按技术路线或问题分类，不按年份罗列；每类开头一句导读，结尾写"这类方法的局限，以及本文与之的区别"；逐篇介绍时一句讲一个机制（"X 等[n]提出……，用于……"）。
  引言里每一处"首次""创新"，都要在这一节找得到对应的比较对象。
- **方法**：先单列问题定义和符号；方法分小节，与贡献一一对应；每个模块按"动机、做法、对应哪条贡献"组织；有算法时给伪代码和复杂度；长证明放附录，正文写定理的作用。
- **实验**：数据集 → 基线（带引用和年份）→ 设置与超参 → 指标 → 主结果 → 消融 → 敏感性与泛化 → 误差分析和可视化 → 案例 [实测]。
  叙述先给事实再给解释（"表 3 显示……，例如 X 在 Y 上从 a 提升到 b，说明……"）；没有取得优势的设置也要写，并给原因。
- **结论**：提炼而不是复述；局限写具体（在什么条件下失效、没测过什么），不写"未来将进一步深入研究"。章名常用"总结与展望"。
- **一致性**：摘要、引言的贡献、实验表、结论四处的同一个数字逐一核对。精读的一篇《计算机学报》论文里，摘要和贡献中的提升百分比相差 0.1~0.6 个百分点 [实测]。

## 综述
- 要有分类轴，不罗列文献：好的综述在引言里逐一点评已有综述的分类视角和时间范围，再亮出自己的视角 [实测]；
  正文是问题定义 → 分类框架（写明分类依据）→ 逐类方法 → 同一数据集和指标下的横向对比表 → 逐类局限 → 相邻问题比较 → 展望。
- 判断有没有"创新性学术观点"（《计算机学报》明文要求）：是否提出了新的分类轴或统一视角，或给出了经过验证的比较结论。
- 叙述发展脉络时按阶段分段，每段点名具体工作（方法名、团队、年份、关键数字），讲清这一阶段解决了什么、留下了什么，自然引出下一阶段。
  重要的阶段多写，次要的一两句带过，不给每段配对称的总结句。
- 缺口写成"故事里缺的那一环"，有证据支撑（"现有评测均在同分布设定下进行[a][b]，跨域表现未见报告"），不写成"未来可从 A、B、C 多方面改进"。

## 开题报告与学位论文
- 开题常见结构：选题依据与意义 → 国内外研究现状 → 研究目标与内容 → 研究方法与技术路线 → 创新点 → 研究基础与可行性 → 进度安排 → 参考文献。
  文献数量和新近性各校不同（硕士常见 30~80 篇、博士 50~150 篇，近五年的常要求三分之一以上），以本校文件为准 [规范，转引多校]。
- 开题写的是"拟做"，要把已有结果和计划分开；研究问题、研究内容、技术路线、章节四者一一对应。
- 创新点写成可检验的陈述，并配验证方案："首次在 X 条件下实现 Y，指标 Z 从 a 提高到 b；对照为……，若……则否定该假设"。
- 实验型课题在"研究内容"里为每个子问题写明数据、对照方法、指标和预期报告的量，这就是后续实验章的骨架。
- 章节之间用一两句交代承接关系，不在每章开头重复全文概述。

## 中英文摘要
- 内容宜对应，英文可以更长（6447 4.3）；题名、作者、单位、关键词同时译成英文（6447 7.9）。
- 《计算机学报》对英文摘要的要求：短句；做了什么用过去时，结论用现在时；多用主动；首句不重复题名；方法部分指向公式和图表 [规范]。
- 中国作者的英文摘要普遍偏短、一般过去时偏少（语料研究，只见摘要页）[实测，转引]。常见问题：逐句直译中文，保留零主语和长定语，变成一串被动句；
  关键词中英文数量顺序不对应；缩略语只在中文版给了全称。
- 推荐流程：先按四要素写英文要点（每要素一到三句，带数字），再据此写中文摘要，不拿中文机翻。英文部分的写法见 [academic-language-en.md](academic-language-en.md)。

## 论断
- 判断放在框架、取舍、强调这一层，每个事实、指标、引用都带出处，零编造。
- 引用对应具体论断：这篇文献支撑的是哪句话，不是笼统挂在段尾。
- 没核实到的写明"未核实"或不写。

## 学术中文的常见语病
通用的中文语病（翻译腔、"的"字、被动、名词化）见 [lang-zh.md](lang-zh.md)。下面是论文里特有或特别多见的几类；国标对语言只有原则要求，
没有找到统计这些语病频率的研究 [观察]，改前改后均为示意。

| 类型 | 改前 | 改后 |
|---|---|---|
| 空洞的"研究" | 本文对该问题进行了深入的研究和分析 | 本文分析了该问题的成因，并给出三种解法 |
| 介词框架吞掉主语 | 通过引入注意力机制，使模型的性能得到提升 | 引入注意力机制后，模型性能提升 |
| 句式杂糅 | 本方法基于卷积神经网络的基础上设计 | 本方法基于卷积神经网络设计 |
| "具有……的特点" | 该方法具有计算量小的特点 | 该方法计算量小 |
| "是……的"判断句 | 该模块是用来提取全局特征的 | 该模块提取全局特征 |
| 术语不统一 | 前文"跨模态注意力"，后文"交叉注意力机制"，图中写"cross-attn" | 全文统一为"交叉注意力"，首次出现附英文 cross-attention |
| 代码式写法 | 学习率 lr=1e-5，batch=32，epoch 数为 50 | 学习率 1×10⁻⁵，批大小 32，训练 50 个周期 |
| 口语和夸张 | 我们的方法效果非常好，大大超过了其他方法 | 在 CIFAR-100 上，本文方法的准确率为 0.860，比次优方法高 2.1 个百分点 |
| 绝对和相对不分 | 准确率提高了 3% | 准确率由 0.80 提高到 0.83（提高 3 个百分点，相对提高 3.75%） |
| 人称混用 | 摘要用"本文"，引言里"本篇工作""我们"混用 | 选一种，全文统一 |

摘要里省略主语是期刊的常规写法（"为此，提出一种……"），前提是整句施事一致、没有歧义；正文里要补主语。
修改时每轮只改一类：先看段落首句是否给出本段要点，再改逻辑词和主语，再删虚化动词，最后核对术语、符号、数字、单位。

## 示例
- ✗ "Transformer 在该领域扮演着至关重要的角色。值得注意的是，后续工作首先在效率方面进行了改进，其次在长序列建模方面也取得了显著提升。"
- ✓ 投稿体："Transformer 是该方向的共同起点。后续改进沿两条线展开：一是降低自注意力的二次复杂度[linformer][performer]，二是扩展长序列建模[longformer]；前者已较成熟，后者仍在演进。"
- ✗ "这一阶段的核心目标是验证单机飞行能力……为后续城市级应用提供了基础数据支持，标志着无人机从实验室走向应用的关键起点。"
- ✓ "最早一批项目只解决一件事：单机在真实城区能不能稳定飞到。Flytrex 在雷克雅未克跨海湾送货是代表，固定起降点、短航线、3 kg 载重，把 25 分钟车程压到几分钟。"
