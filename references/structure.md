# 标题与篇章结构

结构应该从内容里长出来，而不是先搭好框架再往里填。AI 文的结构问题归结为四种：
层级比内容重、各部分长成一个样、标题只贴标签不表态、到处是预告和复述的脚手架。

单看任何一项都是弱信号，成片出现才说明问题。证据标记同 [deai.md](deai.md)：
[实测] 有人机对照统计；[规范] 写作规范或标准明文；[观察] 编辑和社区经验，未量化。

中文写作对此早有批评：毛泽东在《反对党八股》里说"甲乙丙丁，开中药铺"；
2019 年中办通知要求"防止穿靴戴帽、冗长空洞"。AI 的总分总、层层编号，是同一种毛病的新版本。

## 1. 标题层面

| 问题 | 例子 | 依据 |
|---|---|---|
| 一个标题下只有一两句话 | "## 背景"下一句，"## 动机"下一句 | [规范] Wikipedia 格式手册：单句和短段不值得单独设小标题 |
| 层级比篇幅重 | 一页的文字用了三级标题；短回答也分节 | [规范] 微软：一两页通常一级标题就够；plain language：不超过三级 |
| 某一级只有一个小标题 | 2.1 下面没有 2.2 | [规范] Chicago / APA：每级至少两个，否则不分 |
| 序数词充当小标题 | 连续三个以上"一、""二、""三、"引出一两句话 | [实测] 中文语料 AI 是人类的 3.1 倍 |
| 标题只贴标签 | "性能分析""主要发现""Key Findings""Overview" | [规范] plain language、微软：标题要具体，最好写成判断 |
| 固定的收尾小节 | "挑战与展望""结语""总结""Key Takeaways""Future Outlook" | [观察] Wikipedia：问题在套路公式，不在提到挑战本身 |
| 每节都是"X：Y"冒号式标题 | "一、原理篇：AI 为什么写什么都一个味？" | [观察] |
| 标题复述了引言里的大纲 | 引言列出 A、B、C，后面三个标题正是 A、B、C | [观察] unslop 扫描器的强信号之一 |
| 英文正文标题全部首字母大写 | Impact of Technology and Digitalization | [观察] 以期刊模板为准，IEEE 二级标题本来就用 title case |
| emoji、箭头、分隔线装饰标题 | "🚀 快速开始" | [观察] 较早期模型的特征 |

问句标题不是 AI 痕迹：中文语料里人类正文用设问远多于模型 [实测]；plain language 规范还推荐在查阅型文档里用问句标题 [规范]。
论证型文章（论文、评述）少用即可。

## 2. 段落骨架

- **维度切片与"方面"枚举（总—分分分）**：最典型、也最容易被一眼认出的结构，单列在第 3 节。
- **一是 / 二是 / 三是、其一 / 其二、First / Second / Third** 用来罗列本无先后的内容。
  "首先……其次"本身在中文语料里没有区分度（段首衔接词 AI 14.4%、人类 15.1%）[实测]；问题在于用序号代替了因果和主次。
- **加粗标签段落**："**性能**：……""- **Cost:** Lower." [观察，多个工具都列为高信号]。
  GPT-4 当评委时，被判更好的回答 32% 带加粗，被判更差的只有 9%：这种偏好是训练出来的 [实测]。
- **该写成段落的列表**：论证、取舍、解释被拆成要点，每条之间的转折和因果都丢了 [规范] Wikipedia、Anthropic 与 OpenAI 的写作指引都要求论证用散文。
- **空转句加冒号引出**："我见过的几种典型场景：""核心结论先给你：" [实测] 9.4 倍。
- **段首无指代的评论句**：段落以"这一点至关重要。""这正是问题所在。"开头，"这"没有前文可指 [实测] 4.4 倍。
- **相邻句同一骨架**：连续几句同主语、同句式（"AI 可以提高效率。AI 可以降低成本。AI 可以改善体验。"）[实测] 2 倍。
- **顿号并列过密**：一句里堆五六个顿号并列项 [实测] 1.8 倍。
- **预告—展开—复述**："本节从三个方面讨论……" → 三段 → "综上，这三个方面表明……"；全文、每节、每段都有小结。
  结尾段复用开头段的词汇，是 unslop 扫描器里最强的单项信号 [观察，小样本]。
- **每节同一内部模板**：每节都是"背景—方法—意义"或"定义—三个要点—一句总结"，换主题不换骨架 [观察]。
- **每段以一句短促金句收尾**，或连续多段只有一句短话 [观察]。
- **段落可互换**：把任意两段对调，文章读起来差不多。说明这是并列清单，不是论证 [观察，avoid-ai-writing 的诊断法]。

## 3. 维度切片式行文："从 A 层面……从 B 层面……"

### 长什么样
- 中文："从技术层面看……；从应用层面看……；从产业层面看……"；"在 A 方向上……，在 B 方向上……"；
  "可以从宏观、中观、微观三个维度理解"；"就理论而言……就实践而言……"；"短期看……长期看……"；
  "该方法具有以下几个方面的优势：在精度方面……；在效率方面……；在鲁棒性方面……"。
- 英文："On the technical front, … On the business side, …"；"From a X perspective, …"；"In terms of X, …; in terms of Y, …"；
  "At the X level"；"This can be understood on three levels"；"across multiple dimensions"；"Here's a breakdown"。
- 常见配套：开头一句预告（"可以从以下几个层面来看："），结尾一句复述（"综合以上几个层面，……"）。
  段落版是"方面"枚举，标题版是"一、技术维度 二、应用维度 三、社会维度"，列表版是"**技术层面**：……"。

### 为什么一看就像 AI
1. 维度是通用的，不是从问题里长出来的。技术 / 应用 / 产业 / 政策 / 社会，理论 / 实践，短期 / 长期，
   宏观 / 微观，这套格子能套在任何主题上。用第 2 节的"换主题测试"一试就露馅。
2. 维度之间没有关系。每格各说各的，不互相约束；而真正的分析恰恰发生在维度交叉处
   （"精度涨了 3 个点，代价是延迟翻倍，部署端扛不住"）。
3. 每格分量一样，各填一两句，像在填表；没有一格被写透。
4. 切片代替了论证：读者拿到的是一个分类，不是一个判断。中文评论把这叫"看似面面俱到，但每个方向都浅尝辄止"。
5. 成因（推断）：模型不确定读者要什么，就每个方面都说一点，总有一处能压中；偏好训练又奖励"全面""有条理"的外观。

证据：[观察] 使用者经验里 Gemini 和国产模型的中文输出尤其常见；中文去 AI 味教程把"从多个维度来看"列为 AI 腔；
知乎评论描述 AI 文"拆成数个子话题，然后 1234 列出来，走经典总分总"。公开资料里没有找到人机对照统计，
也没有找到把它归给某一家模型的测量；给别人看的材料里写成"常见"，不写成"已证实是某模型的特征"。
相关的实测项：空转句加冒号引出列表 9.4 倍、序数词小标题 3.1 倍、相邻句同骨架 2 倍（lieflat）。

### 什么时候不算毛病
- 维度来自问题本身，并且彼此有张力："从误差看它更好，从计算量看它更差，取舍取决于部署端"。这里的对照就是论点。
- 固定的分析框架：复杂度分析分时间和空间，安全分析分机密性、完整性、可用性，评价协议分数据集和指标。
- 文体要求：公文、项目申报书、述职按规定的"几个方面"写；按模板保留，只在每一项里写实。
- 两项的"一方面……另一方面"只要两边真有对立，就是正常写法。

### 怎么改
1. 先找出真正的结论，问一句：这几个维度里，哪一个决定结论？把它放在最前面写透，其余作为条件、代价或例外出现，没有作用的删掉。
2. 用因果链、时间顺序或读者的问题组织，不用维度组织。
3. 维度确实需要并列比较时，做成表格（维度 × 方案），表里放数字；正文只写从表里读出的那个判断。
4. 删掉预告句和复述句；只有一个维度有实质内容时，就只写这一个。
5. 改完再做一次换主题测试：换个领域这段话就不成立了，才算改好。

改前："从技术层面看，该方法提升了检测精度；从应用层面看，该方法便于部署；从产业层面看，该方法有望推动行业发展。"

改后（数字示意，须来自作者）："该方法把检测精度提高 3.1 个百分点，模型只有 4 MB，能直接跑在门禁终端上。
能不能推广，取决于终端厂商是否开放原始图像接口，这一点目前还没有答复。"

Before: "On the technical front, the model improves accuracy. On the practical side, it is easy to deploy.
From a broader perspective, it opens new avenues for the field."

After: "The model gains 3.1 points of accuracy and fits in 4 MB, so it runs on the door terminal without a server.
Whether vendors adopt it depends on access to raw frames, which none has granted yet."

## 4. 什么时候该分标题、该用列表

- 标题是给读者导航用的。读者需要跳着找时才分标题；一篇文章只讲一个论证时，不分标题。
- 每一级至少两个小标题；一两页的文字通常一级就够；全文不超过三级 [规范]。
- 标题比它下面的内容短；同级标题句式平行；写成具体判断（"Dropout 只在样本少于 1 万时有害"）好过话题词（"Dropout 分析"）。
- 列表只给三类内容：并列的、有先后的、需要比较的；一项不成列表；列表前用一句完整的话引出 [规范] Google、微软。
- 有因果、转折、条件、主次的内容写成段落；多维对比用表格；步骤用有序列表。
- 期刊、专利、公文有固定结构的，按固定结构走，在结构内部改写正文，不自己发明标题。

## 5. 怎么改

1. **合并一句话小节**：把只有一两句的小节并入相邻段落，用段首主题句承担导航。
2. **把"方面"枚举和维度切片改成有主次和因果的段落**（详见第 3 节）。
   - 改前："该方法具有以下几个方面的优势：在精度方面，达到 92.1%；在效率方面，速度为 30 fps；在鲁棒性方面，噪声下下降 3 个点。"
   - 改后："该方法精度达到 92.1%，速度仍有 30 fps，次优方法要用 4 倍大的骨干才能追平。代价是对噪声更敏感，加噪后下降 3 个点，这一点基线方法没有。"
   - 先说最重要的，再说代价和限制；连接词承担关系，不靠序号。
3. **加粗标签列表改成一句话或一张表**：各项真能并列比较的，做成带数字的表；其实是一个论证的，写成一句有主次的话。
4. **标题写成结论**："性能分析与主要发现" → "Dropout 只在样本少于 1 万时有害"；"结语与展望"在论文里按其职能命名（"局限"），在其他文体里直接删。
5. **删预告和复述**：第一句就给第一个论点；结尾停在最强的结论或尚未解决的问题上。
6. **按内容形状选结构**：

   | 内容 | 结构 |
   |---|---|
   | 步骤 | 有序列表 |
   | 参数、选项、多维对比 | 表格 |
   | 少量短的并列项 | 前有引导句的无序列表 |
   | 论证、取舍、解释 | 段落 |
   | 需要跳读的长文档 | 标题（平行、具体、层级少） |
   | 短回答、消息、邮件 | 不分标题 |

7. **打破对称**：重要的部分给更多篇幅，次要的一段带过，可以不设标题。
8. **按文体保留**：论文的固定章节、编号的贡献列表、Methods 子节、术语定义处的加粗；专利的法定结构和步骤编号；
   spec 的参数列表和编号步骤；公文的"一、（一）1.（1）"层级，都保留。GB/T 9704 只规定层次序数怎么写，没有要求用满四层。

## 6. 文体宽严

| 结构项 | 论文 | 专利 | 汇报 / PPT | 技术文档 | 随笔 / 文章 |
|---|---|---|---|---|---|
| 固定章节标题 | 按期刊 | 按法定结构 | 按模板 | 可用 | 少用 |
| 编号列表 | 贡献列表可用 | 步骤编号 | 可用 | 步骤可用 | 不用 |
| 加粗标签列表 | 不用 | 不用 | 少用 | 参数说明可用 | 不用 |
| 结论小节 | 必需，但不复述摘要 | 不适用 | 一页结论页 | 不需要 | 不用 |
| 摘要、TL;DR 复述主旨 | 正当 | 正当 | 正当 | 正当 | 少用 |

## 7. 阈值速查（经验值；脚本查其中能机械判断的几项，"结尾复述开头"要人工看）

- 300 字（英文词）以内超过 3 个标题；200 字以内超过 8 个要点（avoid-ai-writing）。
- 每节加粗不超过 1–2 处（unslop、avoid-ai-writing）。
- 连续 3 个及以上序数词小标题（lieflat，实测 3.1 倍）。
- "**标签**：内容"式行达到 3 行（unslop，技术文档可放宽）。
- 一个标题下的正文少于两句。
- 结尾段与开头段共享 2 个以上实词（unslop，小样本）。
- 一段里出现 3 处及以上"从 X 层面 / 在 X 方面 / 就 X 而言"或 "on the X front / from a X perspective / in terms of"（经验值，无实测）。
